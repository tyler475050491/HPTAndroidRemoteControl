## 2. 代码地图（按职责）

| 文件 | 职责 | 改它时的注意点 |
|---|---|---|
| `MainActivity.java` | 全部 UI 与业务流程（约 2000 行）：连接/刷新/搜索、设备列表、投屏、全屏、安装/卸载、日志 | 所有交互都在这里；改 UI 后真机坐标会变，截图验证时要重新取点 |
| `AdbConnection.java` | ADB 报文编解码 + socket 收发（CNXN/AUTH/OPEN/OKAY/WRTE/CLSE） | **报文头 24 字节 = cmd, arg0, arg1, len, crc, magic，magic 必须 = cmd ^ 0xFFFFFFFF**，写 0 会被 adbd 静默丢弃 |
| `AdbCrypto.java` | RSA 2048 + SHA1 签名，输出 Android 私有 `RSAPublicKey` 结构 | 设备关 AUTH 时不走这里；改结构体字段顺序会握手失败 |
| `AdbDevice.java` | 设备级操作封装：`shell:` / `exec:` / 推流 / `installApk` / 列包 / 卸载 / 重启 | `installApk` 就是"边解密边上传"的落地处 |
| `AdbStream.java` | 单条流的读写（对应一个 OPEN/OKAY 的 local-id） | 流关闭收到 CLSE 只标记 + 移除，**绝不回包** |
| `ScrcpyServer.java` | 推 jar、校验大小、`killOld()` 清残留、拉起 `app_process` | 必须用 `shell:` 而不是 `exec:`；必须 `cleanup=false` |
| `ScrcpyControl.java` | scrcpy 控制通道：32 字节大端 `INJECT_TOUCH_EVENT`、20 字节滚动 | 视频头读完必须 `setVideoSize(w,h)`，否则服务端忽略触摸 |
| `ScrcpyMirror.java` | 投屏主流程：读视频头 → MediaCodec 解码 → 直出 Surface；触控单线程下发 | 解码循环里 `releaseOutputBuffer` 必须 try/catch，**不能让解码线程退出** |
| `ScreenMirror.java` | 截图流兜底（scrcpy 不可用时用 `screencap` 轮询） | 只兜底，别当主力 |
| `PreviewView.java` | 预览画布：`MODE_EMPTY/BITMAP/VIDEO`、等比居中、旋转反算、手势分发 | `onSurfaceTextureDestroyed` **必须返回 false**（否则全屏黑屏） |
| `BuiltinApkStream.java` | 内置包密文流式解密（分块 AES-GCM） | 容器头 keyCheck 不匹配会报"密钥与本机签名不一致" |
| `Secret.java` | 密钥派生（口令字节表 XOR + 签名证书绑定） | **与 build.gradle 的 syncBuiltinApk 必须同步改**，见第 4 节 |

## 4. 更换内置安装包（最常见需求）

**结论：直接把新的 `.apk` 丢进 `E:\豆包\HPTADB\apk\`，重新 clean 打包即可，包名不同也能用。**

流程与自检点：

1. `apk\` 下可以有多个 `.apk`，构建任务取**修改时间最新**的那个；建议一次只留一个，避免拿到旧包。
2. 构建时 `syncBuiltinApk`（`preBuild` 依赖）会：
   - 用 aapt 解析新包的**包名和应用名**（aapt 在中文路径下会失败，所以先复制到 `java.io.tmpdir\hpt_builtin_probe.apk` 再解析）；
   - 用"口令 + 签名证书"派生的 AES-256 密钥做 4MB 分块 GCM 加密，输出 `assets\hpt_payload.dat`；
   - 写 `assets\payload.idx`（`package/label/size/encSize/sha256`）；
   - 删掉旧的 `builtin.apk` / `builtin.apk.enc` / `builtin_info.properties`。
3. **包名不做任何硬编码**，运行时全部来自 `payload.idx`：
   - 「安装软件」弹窗显示 `label` / `package`；
   - 安装走 `adb install -r -d`（不依赖包名）；
   - 「卸载软件」列表来自设备侧 `pm list packages -3`，只用 `package` 去匹配 `label` 显示（不匹配就只显示包名，功能不受影响）。
4. 换包后要重新 clean 打包（asset 会重新生成）；同一版本号换包，安装到设备时 `-r` 覆盖即可。
5. 已实测：把 `apk\` 换成 `com.android.adbkeyboard`（17,374 B，包名与应用名都不同）→ `payload.idx` 自动变成 `package=com.android.adbkeyboard / label=ADBKeyBoard` → 真机「安装软件」成功、「卸载软件」列表正确显示 `ADBKeyBoard（com.android.adbkeyboard）`、设备临时文件按预期删除。

> 已知边界：如果新包是**拆分 APK**（base + config 分离）或 **AAB**，本工具只支持单文件 APK。遇到拆分包需先合并成单一 APK，再放 `apk\`。文件名保持 `.apk` 后缀即可，中文名也可以（aapt 解析前会复制到临时 ASCII 路径）。

## 5. 加密方案（改它必须三处同步）

密钥派生（构建期与运行期必须完全一致）：

```
key = SHA-256( "HPT2026#AdbTool#Builtin|hpt-builtin-apk-v1"  ‖  '|'  ‖  SHA-256(签名证书 DER) )
```

- 构建侧：`app\build.gradle` 的 `syncBuiltinApk`，从 `keystore.properties` 指向的 jks 取证书 DER。
- 运行侧：`Secret.key(Context)`，口令以 XOR 0x5A 的 `int[]` 存（`BLOB`），运行时还原；证书用 `PackageManager` 取（API 28+ 走 `GET_SIGNING_CERTIFICATES`，以下走 `GET_SIGNATURES`）。
- 容器格式：`"HPTK"(4) | ver(1)=2 | chunkSize(4) | chunkCount(4) | keyCheck(4) | { iv(12) | ctLen(4) | ct } × N`；
  `keyCheck` = `SHA-256(key)` 前 4 字节，客户端解密前先比对，不匹配直接提示"密钥与本机签名不一致"。

要换口令 / 换盐 / 换证书：**同时改 `Secret.BLOB`（重新按 XOR 0x5A 生成字节表）与 `build.gradle` 的 `BLOB` 字符串**，然后 clean 打包。只改一边会导致内置包解不开。

## 7. 协议层已知暗坑（照抄结论，别再踩）

1. CNXN 报文头 `a0` = 版本 `0x01000001`，`a1` = `maxData=262144`（不是反的）。
2. 报文 `a0` = 发送方 local-id，`a1` = 对端 remote-id。
3. 收到 `CLSE` 只标记关闭并从表里移除，**绝不回包**（回包会让 adbd 断链）。
4. 报文头 magic 必须 `cmd ^ 0xFFFFFFFF`。
5. PM 操作后设备 dexopt 占满 CPU，adbd 1~2 分钟不响应新 OPEN → 有 `ensureAlive()` 重连兜底。
6. scrcpy 2.7 服务端选项是 `video_bit_rate`（写 `bit_rate` 会 `Unknown server option` 直接退出）。
7. 视频头顺序：1 字节哑 `0x00` → 64 字节设备名 → 4 字节 fourcc → 4 字节宽 → 4 字节高（共 76 B）；之后每包 `pts(8, bit63=config/bit62=key) + size(4) + data(Annex-B)`；**必须先连控制通道，服务端才继续发头**。
8. `pts` 高两位是标志位，喂解码器前要 `pts & 0x3FFF_FFFF_FFFF_FFFFL` 并做单调保护，否则 QTI 解码器报 `err 0xffffffe0 / DEAD_OBJECT`。
9. `releaseOutputBuffer(idx, false)` 不渲染，必须 `true`。
10. `app_process` 加载不到类会 `SIGABRT`；jar 每次投屏都要重推 + `cleanup=false`。
11. 设备 adbd 偶发拒 `localabstract:scrcpy`（环境问题）：每次投屏前 `pkill -9 -f com.genymobile.scrcpy.Server`、必要时 `adb forward --remove-all`。
12. **OPEN 的服务名字符串必须补结尾 `\0`**（`AdbConnection.openStream` 里统一处理）。实测 Android 11 的 adbd 对 `localabstract:scrcpy` 是整串比对：不带 NUL（`a0` 长度正好 20）直接回 `CLSE`，日志表现为「设备拒绝打开该服务（可能不支持该 adb service）」，30 次重试全部失败、投屏卡死；带 NUL（长度 21）立刻回 `OKAY`，视频流正常。`shell:` / `exec:` / `sync:` 同样应带 NUL（官方 adb 客户端就是带 NUL 发的）。

## 9. 加固与分发

- 正式版必开 `minifyEnabled + shrinkResources`（R8），类会被改名并压进 `hpt.*`，只有 Manifest 注册的 `MainActivity` 保留类名。
- 内置包不进 assets 的明文，只留 `hpt_payload.dat` 密文；密文与签名证书强绑定（换证书重打包即解不开）。
- 交付件：`HPT移动端ADB助手.apk`（根目录）+ `doc\` 下的说明与截图；`mapping.txt`、keystore 不随包外发，但要自己备份。
